# Virgule status and plans

Status: Mac-only implementation in progress · revised 2026-11-18. The app plan covers LaTeX, Markdown, and other readable files on Mac.

**Virgule** is the app name on `main` (`PRODUCT_NAME` and `CFBundleDisplayName`, version 0.1 build 3). It is a candidate name and has not been cleared as a trademark. The bundle ID stays `app.libreweave.LibreWeave`, and the Xcode target/scheme, Swift module and test target keep the `LibreWeave` names, so preferences, recent documents and Finder default-app choices carry over. The GitHub repository is **`ayushmk7/Virgule`** (renamed from NativeLatex; GitHub redirects the old URL). **NativeLatex** remains the Xcode project, source folder, and Swift package name. Minimum macOS is **14.0** for the app and both packages.

**Rebrand state (2026-11-18):** the owner authorized the local Virgule implementation ([brief](prompts/virgule-implementation.md), [coordinated plan](virgule-rebrand-plan.md)). Done on `main`: visible app, Design demo and Integrations copy, LibreTexts User-Agent, slash icon, and landing copy. The local install is `~/Applications/Virgule.app` (ad-hoc signed), and `.tex`, `.md` and `.txt` open with it. The public cutover is done: the repository is `ayushmk7/Virgule`, the Virgule page is live at <https://virgule.ayushmadhav.com/>, and <https://libreweave.ayushmadhav.com/> returns a 301 to the same path and query there (Vercel project `libreweave-redirect`, from `deploy/libreweave-redirect/`). The re-rendered demo cuts, light poster and GIF (`6d1caf7`) show Virgule; their file names keep `libreweave-*`. There is still no public app download.

**Earlier names:** LibreWeave was the working name from 2026-11-17 until the Virgule rename. The previous working name, LibreLeaf, was dropped on 2026-11-17 because another LaTeX editor already uses it. Exact-name web and GitHub searches found no project called LibreWeave on that date. That is not a trademark search or clearance. The app target, Swift module and entry point (`LibreWeaveApp`) still use LibreWeave. Older names are also kept on purpose, as stable migration identifiers: the old preferences domain `app.libreleaf.LibreLeaf` (read once for the build owner token and the BB-8 appearance), the build folder `.libreleaf-build/`, its `.libreleaf-owner` marker and the `LibreLeaf.log` file inside it, so existing build output stays owned. The landing theme key `libreweave-theme`, the shared Markdown style keys, the `libreleaf-local` scheme and the `landing/media/libreweave-*` file names are also kept.

## Workspace layout

The existing Herdr **NativeLatex** workspace is the primary space. Art, UX, Backend, Integrations, Landing, Adversarial, and Brag are linked sidebar workspaces with their own Git worktrees. Mobile was removed because the product is Mac only. Four Claude sessions in Adversarial review functionality, security, accessibility, and build/release behavior. Changes reach the primary branch when merged. In the planned app, a *workspace* will mean an ordinary local project folder in its own macOS window; the current build opens one file per window.

## This Mac's toolchain

Xcode 27.2 works with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`; system `xcode-select` still points to Command Line Tools because changing it requires an administrator password. TeX is **Homebrew texlive** (`latexmk`, `pdflatex`, `synctex` in `/opt/homebrew/bin`). `/Library/TeX/texbin` exists only as a broken symlink chain left from a removed MacTeX 2024 (`/usr/local/texlive` is gone), so it contains no binaries; the build service checks each candidate resolves to a real executable. Pandoc 3.13 and LibreOffice (`/opt/homebrew/bin/soffice`) are present. See the [deployment readiness checks](deployment-plan.md#current-readiness-on-this-mac).
