# LibreWeave status and plans

Status: Mac-only implementation in progress · revised 2026-11-17. The app plan covers LaTeX, Markdown, and other readable files on Mac.

**LibreWeave** is the working app name (product name, bundle `app.libreweave.LibreWeave`, scheme `LibreWeave`). **NativeLatex** remains the repository, Xcode project, folder, and Swift package name. Minimum macOS is **14.0** for the app and both packages.

The previous working name, LibreLeaf, was dropped on 2026-11-17 because another LaTeX editor already uses it. Exact-name web and GitHub searches found no project called LibreWeave on that date. That is not a trademark search or clearance. The app target, Swift module (`LibreWeave`), entry point (`LibreWeaveApp`) and user-facing text use the new name. These keep the old name on purpose, for migration: the old preferences domain `app.libreleaf.LibreLeaf` (read once for the build owner token and the BB-8 appearance), the build folder `.libreleaf-build/`, its `.libreleaf-owner` marker and the `LibreLeaf.log` file inside it, so existing build output stays owned.

## Workspace layout

The existing Herdr **NativeLatex** workspace is the primary space. Art, UX, Backend, Integrations, Landing, Adversarial, and Brag are linked sidebar workspaces with their own Git worktrees. Mobile was removed because the product is Mac only. Four Claude sessions in Adversarial review functionality, security, accessibility, and build/release behavior. Changes reach the primary branch when merged. In the planned app, a *workspace* will mean an ordinary local project folder in its own macOS window; the current build opens one file per window.

## Implemented on main (checked 2026-11-17)

The final merged test target compiled headlessly (`/tmp/libreweave-merged-bft.log`); app-hosted tests were not rerun because they can bring windows over the owner’s work.

The binary has `arm64` and `x86_64` slices, targets macOS 14.0, is ad-hoc signed with Hardened Runtime (`flags=0x10002`), and passes `codesign --verify --deep --strict`. LaunchServices now registers only this LibreWeave bundle; 27 stale test-build registrations were removed. It is not Developer ID signed or notarized. **Planned, not implemented:** folder workspaces (one folder per window, file tree, tabs, recent folders), root-file selection, SyncTeX, XeLaTeX/LuaLaTeX profiles, live Google Docs/OneDrive sign-in, LibreTexts publishing.

**Release blockers:** Developer ID signing and AWS hosting need the owner's real Apple Developer and AWS credentials, which this workspace does not have (0 valid signing identities, no AWS session). There is no notarized build, no S3/CloudFront resource, no clean-Mac or TeX-absent test, and no Intel test. **There is no signed Mac download.**

## This Mac's toolchain

Xcode 27.2 works with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`; system `xcode-select` still points to Command Line Tools because changing it requires an administrator password. TeX is **Homebrew texlive** (`latexmk`, `pdflatex`, `synctex` in `/opt/homebrew/bin`). `/Library/TeX/texbin` exists only as a broken symlink chain left from a removed MacTeX 2024 (`/usr/local/texlive` is gone), so it contains no binaries; the build service checks each candidate resolves to a real executable. Pandoc 3.13 and LibreOffice (`/opt/homebrew/bin/soffice`) are present. See the [deployment readiness checks](deployment-plan.md#current-readiness-on-this-mac).
