# Virgule Mac release and deployment plan

Status: planning and readiness checks · revised 2026-11-18. The app is now named **Virgule** (bundle ID unchanged: `app.libreweave.LibreWeave`; scheme still `LibreWeave`). The repository is `ayushmk7/Virgule`, and the Virgule landing page is live on GitHub Pages at <https://virgule.ayushmadhav.com/>; the old host <https://libreweave.ayushmadhav.com/> 301-redirects to it. A local, ad-hoc-signed universal Release archive builds from `NativeLatex.xcodeproj`; no Developer ID signature, notarized artifact, download, or AWS resource exists.

## What needs hosting

The native Mac app edits and builds locally. Its single owner can use Google Drive or OneDrive through optional, user-authorized client integrations. No account service, TeX server, database, or sync API is part of this release. A website is **optional**: it can explain the app and link to a download, but it does not run the app.

| Surface | Decision | Reason |
| --- | --- | --- |
| Mac app | Build locally in Xcode; distribute a signed, notarized ZIP | It launches the user's TeX tools and opens ordinary folders. |
| Download artifact | Private S3 origin behind CloudFront | Keeps the user's preferred AWS hosting for the released ZIP and checksum. |
| Landing page | Static `landing/` on GitHub Pages via `.github/workflows/pages.yml`, linking to the AWS artifact | No app runtime, login, or build step; the repository is public, so Pages needs no extra account. Vercel stays an alternative but its Hobby terms restrict commercial use. |
| Updates | Publish a new versioned ZIP and release notes manually | No updater service is needed for one owner. |

Vercel documents the [Hobby restriction](https://vercel.com/docs/plans/hobby). CloudFront's $0/month flat-rate Free plan currently includes a baseline of 1 million requests, 100 GB delivery, and 5 GB of S3 Standard storage credits per month; other AWS usage can still be charged. Serve a private S3 bucket through Origin Access Control and verify the actual billing configuration before publication. [CloudFront plan](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/flat-rate-pricing-plan.html). The separate AWS new-account Free plan expires after at most six months or when credits are exhausted. [AWS Free Tier FAQ](https://aws.amazon.com/free/free-tier-faqs/).

## Release sequence

Every distributable app must come from **Xcode Archive** (Product ▸ Archive, or `xcodebuild -project NativeLatex.xcodeproj -scheme LibreWeave -configuration Release -destination 'generic/platform=macOS' -archivePath Virgule.xcarchive archive`; the scheme keeps its `LibreWeave` name and the archived product is `Virgule.app`) and then Organizer's Direct Distribution export. Never ship the `.app` from a plain `xcodebuild … build` or the Products folder: a non-archive Release build carries the `com.apple.security.get-task-allow` debugging entitlement, which notarization rejects; the archive strips it (verified: archived app entitlements `{}`, Hardened Runtime on).

Signing, notarization and AWS hosting need the owner's **real** Apple Developer and AWS credentials, used in their own Xcode account and AWS session. They are not in this repository, its workspaces, or any `.env`, and test doubles cannot prove them.

1. **Local app gate:** run the Mac Xcode target on this machine; verify `.tex` and `.md` Open With, local TeX build, Markdown preview, two independent windows, and both appearances. Test a Mac without TeX before calling the app distributable. The build is universal (`x86_64 arm64`); either test it on an Intel Mac or set `ARCHS = arm64` for Release before claiming Intel support.
2. **Signing gate:** set the bundle identifier, version, minimum macOS, app icon, signing team, and Hardened Runtime. With the owner's Apple Developer account, obtain a valid Developer ID Application identity in the keychain. Archive, then use Xcode Organizer's Developer ID/Direct Distribution workflow to re-sign and notarize the archived app. This Developer ID release route requires signing and notarization under Apple's [notarization guide](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution/). Apple lists its Developer Program at US $99/year, subject to local pricing. [Apple enrollment](https://developer.apple.com/help/account/membership/program-enrollment/).
3. **Artifact gate:** staple the notarization ticket to the app, package a versioned ZIP, and record SHA-256. Verify `codesign --verify --deep --strict`, `xcrun stapler validate`, and `spctl --assess --type execute` on the exported app. Download the ZIP to a clean Mac and repeat the launch/build/open checks. The [backend plan](workspaces/backend/architecture.md) has the exact Mac release path.
4. **AWS gate:** with the owner's real AWS credentials, authenticate to the intended account, choose the CloudFront plan, create the private S3 origin and distribution with Origin Access Control, upload only the verified ZIP/checksum, then download and hash the public artifact. Set a budget or usage alert for any paid resources. Publish no user project files.
5. **Landing gate:** `.github/workflows/pages.yml` uploads `landing/` as-is and deploys it with the official Pages actions on pushes to `main` that touch `landing/` (or by manual dispatch). Pages is enabled with **GitHub Actions** as its source, and the workflow run for the landing merge succeeded. The [static page](../landing/README.md) serves the app demo and repository link at <https://virgule.ayushmadhav.com/> (HTTP 200 over enforced HTTPS). The old host stays on the Vercel project `libreweave-redirect` ([config](../deploy/libreweave-redirect/vercel.json)), which answers every path, `/media/*` included, with a 301 to the same path and query on the new host. Keep that project and the old domain while old links circulate ([cutover plan](workspaces/landing/virgule-plan.md)). Add a version, download link, checksum, and Mac requirements only after the artifact gate passes.
