# Landing workspace plan

Status: the LibreWeave page is live on GitHub Pages at <https://libreweave.ayushmadhav.com/>, served from the pushed `main` over enforced HTTPS (`landing` branch changes appear after merge and push) · revised 2026-11-18. Local `main` now has the Virgule copy and the candidate canonical URL `https://virgule.ayushmadhav.com/`; it is not pushed, and that host is not live. Cutover: [Virgule landing plan](virgule-plan.md).

The landing page is a single static page in [`landing/`](../../../landing/README.md), deployed to GitHub Pages by `.github/workflows/pages.yml`. Vercel holds only the domain's DNS record; Vercel hosting remains an unused alternative with that directory as the project root. It uses no framework, build service, account, analytics, or form. While no signed Mac release exists, its single Explore action links to the GitHub project and offers no download. The window graphic is labeled as a concept preview.

The visible product name is **Virgule** on `main` (LibreWeave on the live page until the cutover); the repository keeps the NativeLatex name. The look follows the owner's Website and Internship pages (black/white, system sans, open spacing, pill controls, BB-8 in the top-right corner). Neutrals use the Internship/Apple greys. The only brand blue is the Website base theme's `#2563EB` in both appearances. The app UI, `AccentColor` and icon use the same value. In dark mode all non-blue text is pure white (`#FFFFFF`). Sections and rows have no divider lines, and the workflow heading stays on one line at desktop widths. Sections carry headings only, with no eyebrow labels or step numbers. Copy describes only what `main` does today: one file per window, local TeX builds, and Pandoc Markdown preview. The app is not Developer ID signed or notarized, so the page offers no download. The theme switch reuses the exact Uiverse BB-8 toggle shipped on both of those sites, with its MIT credit. The Mac app has its own native SwiftUI version, `NativeLatex/Design/Sources/NativeLatexDesign/BB8Toggle.swift`, linked into the app's toolbar; the two are matched by eye, not shared code. `landing/icon.svg` is owned by Art and generated by `art/tools/gen.py`.

## Verified state (on main `ce50a3e` plus the Website-blue change, 2026-11-17)

Headless Chrome via `playwright-core` against `python3 -m http.server`, at 1440×900 and 390×844, system light and dark:

- Initial theme follows the system and the BB-8 knob matches it before first paint; Space on the focused switch flips the theme; the choice persists across reload; live system appearance changes are followed until the visitor picks a theme, then ignored.
- No horizontal overflow at either width, before or after toggling. The switch's tap area is 71×45 px at 390 px.
- Switch is reachable by Tab (after skip link, brand, three nav links) and shows a `#2563EB` focus ring in both appearances; reduced motion still toggles; `prefers-contrast: more` (emulated) strengthens neutral text. The heading accent and primary button use `#2563EB` in both appearances, and no `.eyebrow` element remains.
- In-page anchors resolve; both GitHub links return HTTP 200; no console errors or failed requests; visible text says Virgule only (after the cutover) and has no download call to action.
- `#2563EB` on white and white on `#2563EB` are 5.17:1. On black, blue is 4.06:1, so it is limited to large headings and non-text focus rings; small dark-mode text is neutral white.

Not yet done: a VoiceOver pass on the switch (markup is a native checkbox with `role="switch"` and `aria-label="Dark mode"`, but no screen reader was run), and checks in Safari and Firefox.
